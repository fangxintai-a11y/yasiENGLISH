# 个人账号与学习进度同步

在「我的 → 学习进度同步」首次设置个人账号，另一台设备使用同一账号登录。新设备的欢迎页也可直接选择「已有账号，登录恢复进度」。生产首次创建账号需要部署时提供的配对码；默认只允许一个账号，后续不能被其他人注册。

登录后会合并本机已有学习记录。答题后约 1.2 秒上传，页面在前台时每 15 秒检查一次其他设备的更新，恢复联网、切回页面时也会检查。未登录、离线或服务不可用时继续在本机学习，界面明确显示等待同步的状态。浏览器拒绝保存时需先导出备份并释放空间。

「账号管理」支持修改密码、查看当前与其他登录设备、逐个退出其他设备、一次退出其余设备。修改密码会刷新当前设备的登录，并使其他设备重新登录。密码不写入浏览器存储，服务端保存带随机盐的 PBKDF2 哈希；登录凭证使用 HttpOnly、SameSite Cookie，生产启用 Secure。

## 数据放在哪里

| 数据 | 存储 |
| --- | --- |
| 单词三轨复习状态、学习统计、错词、收藏、队列、阅读、跟读统计、考试计划与设置 | 本机 localStorage + 服务器 SQLite |
| 同步基线、待确认提交、应用恢复日志 | 本机 IndexedDB `band-cloud-sync` |
| 跟读录音 | 仅本机 IndexedDB `band-voices` |
| 词库、插图、发音与离线包 | 静态网站文件 + 浏览器 Cache Storage |
| 外部接口设置与密钥 | 仅本机localStorage（band-galaxy:llm、band-galaxy:llm-secret:<id>），只发往你自己填写的接口地址 |

同步不会上传录音、外部接口密钥、进行中的答题轮。JSON 导出仍只包含学习进度和设置。导入和清空会改变账号的同步进度，操作前应保留备份。

## 合并与断网恢复

服务器按账号和词库保存完整 JSON 学习快照，并用递增版本号检查更新。客户端以最后确认的快照为共同基线进行三方合并：不同词的学习保留，同词采用最后复习的完整 FSRS 状态，独立的每日统计按增量相加，收藏与队列保留删除语义。首次连接缺少共同基线时，历史统计采用较大值，避免把两端同一份历史重复相加；首次合并前分别导出备份可保留原始数据。

每次上传带唯一提交标识，数据库同一事务记录快照与提交回执。即使服务器已保存但 HTTP 响应丢失，重试仍能确认原提交，避免重复计数。客户端应用日志和原子保存标记支持浏览器写入中断后的恢复。服务器保留最近 20 版快照，日常数据库备份使用 SQLite backup API。

两端离线修改同一个设置时，后合并设备的该项修改优先；同词以设备记录的复习时间判断新旧，设备时钟应正常。账号已登录并不代表最近的离线记录已上传，应以界面「已同步」为准。

## 开发与验证

需要 Node.js 20+、Python 3.12+。

```bash
npm ci
npm run dev:server
# 另一个终端
npm run dev
```

```bash
npm test
npm run test:server
npm run build
npm run test:sync
```

端到端测试使用临时 SQLite 和独立浏览器上下文，不读取个人浏览器数据。生产部署沿用 GitHub → 本机源码 → 本机打包上传 → 服务器构建，API 独立运行于回环端口，由 Nginx 同源代理；详见相邻的 `BandGalaxy-部署-20261028/README.md`。数据库必须保存在发布目录和静态文件目录外，不能随代码回滚覆盖。
